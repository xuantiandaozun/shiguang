# 桌面整理原则

在 `scan_desktop` 之后、`propose_organization` 之前加载本技能，并按其约束生成方案。

## 分类

- 维度参考：文档、表格、演示文稿、图片、视频、音频、压缩包、安装程序、代码项目、可执行文件等；也可按文件名体现的项目/主题聚合。
- 每个分类只给分类名（如「图片」），目标目录由系统拼成「整理根目录 + 分类名」，扁平一层，不要绝对路径，不要多级目录。
- `files` 数组只放桌面顶层项的 `name`（`scan_desktop` 结果里 `depth=1` 的项），不要放路径或文件夹内部子文件；文件夹可整体作为一个项纳入。
- 桌面上已有的收纳类文件夹（名字像分类名，如「图片」「开发工具」）是以往整理成果，保持原位，不要再纳入 `files`。

## 快捷方式与系统文件

- `.lnk` / `.url` 默认保留在桌面、不纳入方案；数量少时不要动。
- 仅当用户明确要求，或同一主题/类型的快捷方式明显过多时，才按主题聚合（如「开发工具」）；不要为个别快捷方式单独建分类，也不要笼统收进大杂烩「快捷方式」。
- `desktop.ini` 不要纳入方案。

## 不确定与删除

- 拿不准归属的放「待确认」，方便用户在界面剔除。
- 仅当用户明确要求删除，或文件明显是无用垃圾（重复安装包、过期临时文件等）时，才用 `action="delete"`（建议分类名「移入回收站」）。删除=移入回收站，可恢复；拿不准的永远不要删除。
