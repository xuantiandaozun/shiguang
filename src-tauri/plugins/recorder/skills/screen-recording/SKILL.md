# 操作录屏

## 录制

1. 确认要录的网页。需要先打开时用 `record_start` 的 `url`。
2. 两种方式：
   - **用户自己操作**：`record_start` 后告诉用户可以开始了，用户说好了再 `record_stop`。
   - **拾光代为操作**（演示、宣传视频）：`record_start` 后用浏览器工具一步步操作。每一步开始前调用 `record_mark`：label 写步骤名，note 写这一步的解说词。停止录制时，带 note 的标记会自动成为解说草稿。操作放慢，每步之间留 1 秒左右，点击前先把鼠标移到目标上，这样放大效果更自然。全部做完再 `record_stop`。
3. 只录当前标签页。录制中不要切换标签，否则画面会停住。

## 打码

- 密码框、手机号、身份证、邮箱、银行卡、密钥默认在页面上就被模糊，录到的画面里没有明文。
- 页面打码要在**开始录制之前**配置：让用户在「插件 → 录屏」设置里加 CSS 选择器或正则。
- 录完才发现漏了：用 `record_edit` 的 `masks` 补马赛克，也可以让用户在「录屏 → 编辑」里框选。
- 导出后**一定提醒用户看一遍成片**，确认没有漏掉的敏感信息，再对外发。

## 解说词

1. `record_timeline` 读出步骤标记、点击和页面切换（带时间和按钮文字）。
2. 按步骤写解说词，每段挂在对应步骤的时间（`at`）。要求：
   - 口语、简短，一段一两句，说「做什么、为什么」，不念按钮全名；
   - 不要出现被打码的内容；
   - 宣传视频开头加一句介绍，结尾加一句总结。
3. 先把解说词列给用户确认，再用 `record_edit` 的 `narration` 写入。没有配音时，导出只出字幕。

## 配音（用 CLI，不写死接口）

录制器不内置任何配音服务。音频由用户已安装的配音 CLI 生成，比如火山引擎的命令行工具。

1. 先问用户用哪个 CLI；用户没说时用 `run_command` 找一下常见的。用法以它的 `--help` 为准，不要凭记忆拼参数。音色用用户指定的，没指定就先列出可选音色让用户挑。
2. 凭据由 CLI 自己的配置管理，不要让用户把密钥贴进对话，也不要写进命令行参数。
3. 每段解说生成一个音频文件，放到 `record_timeline` 返回的 `audio_dir`。文件名按顺序：`01.mp3`、`02.mp3`……
4. 用 `record_edit` 写回 `narration`，每段的 `audio` 填 `audio/01.mp3` 这样的相对路径，`text` 保留（用作字幕）。
5. `record_export` 加 `preview: true` 先出预览，给用户看效果。

时间对齐是自动的：某段配音比画面长时，画面会在下一步之前定格，等这段说完再继续。所以不需要手动调整时间。

## 剪辑与放大

- 等待加载、操作失误的片段用 `cuts` 剪掉。
- 自动放大不理想时，用 `zooms` 指定放大段；`focus` 为固定焦点，不写则跟随光标。传 `"auto"` 恢复自动。
- 这些也都可以让用户在「录屏 → 编辑」里调。

## 导出

- `record_export`。宣传视频用 `style: "padded"`。字幕默认画进画面，同时生成同名 `.srt`。
- 首次导出会准备 ffmpeg，可能需要下载几十 MB，提前告诉用户。
