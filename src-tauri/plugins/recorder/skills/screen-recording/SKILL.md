# 录屏与截图

## 截图

- 用户说「截个图」「我框一下」：`screenshot`（mode 默认 interactive），会弹出全屏选区，用户自己拖选区域或单击窗口。
- 截某个软件：`screenshot` 的 mode=window，window 写标题或进程名的一部分。不确定名字时先 `list_windows`。窗口被遮挡也能截完整；最小化的窗口要先还原。
- 只要窗口里的一块（mode=window 或 self 都行），三选一：
  - `element`：按控件，如 `{"name": "发送", "role": "button"}`，或 desktop_snapshot 的 `{"ref": 12}`。最准，优先用。
  - `text`：按画面上的文字（本地 OCR 找到那一行），适合控件树读不到的界面；要带上周围内容就加大 `padding`（如 120）。
  - `rect`：窗口截图上的像素坐标 `[x, y, 宽, 高]`。不知道坐标时先整窗截一张看图，再按图上的位置裁。
- 截拾光自己：mode=self，window 写 主窗口 / 对话 / 悬浮球 / 提醒（不写取可见的主窗口，其次对话窗口）。隐藏的窗口会临时显示、截完收起。做拾光宣传素材、检查自己的界面效果时用；也能配合 element 只截某个面板或按钮。
- 全屏：mode=screen。screen / region 默认不包含拾光自己的窗口，要包含时传 `include_self: true`。
- 截图存在「图片/拾光截图」，默认同时复制到剪贴板。当前模型能看图时，window / self 截图会直接附给你；否则用 `read_image` 读返回的路径。
- 用户也可以用全局快捷键（默认 Ctrl+Shift+X）或「录屏截图」页截图。
- 截图里可能有敏感信息，要发给别人或做素材前提醒用户检查。

## 节奏规则（拾光代为录制时必须遵守）

慢、空、长是演示视频最常见的问题。按这些规则来：

| 项目 | 要求 |
|---|---|
| 总时长 | 产品介绍 / 功能演示 45–75 秒；单个功能教程不超过 90 秒。内容多就拆成几条，不要做成一条长视频 |
| 开头 | 前 3 秒就说清「这是什么、能帮你做什么」，不要铺垫 |
| 每段解说 | 一句话，不超过 25 个字（约 4–6 秒）。宁可多分几段，也不要一段说一大串 |
| 画面动作 | 每 3–5 秒要有一个动作：滚动到下一块、鼠标移到关键处、点开一个东西。光滚动页面很单调，能点的就点（点击会触发自动放大） |
| 停顿 | 每段之间最多停 0.3–0.5 秒。不要用固定的等待时间，按配音实际时长等 |
| 结尾 | 一句话收尾加行动号召（例如「GitHub 搜拾光，欢迎 star」），然后马上结束 |

导出默认开启「紧凑节奏」（`tighten`），会自动剪掉画面静止且没有解说的空档。但它只能补救，录的时候就要按上面的节奏来。

## 先配音，再录制（拾光代为操作时的标准流程）

先知道每句配音有多长，录制时画面按配音时长推进，画面和声音天然对齐，不会出现大段空白。

1. **写分镜**：先看页面内容（`browser_read` / `browser_snapshot`），列出 6–12 个镜头。每个镜头包括：一句解说（≤25 字）、对应的画面动作（滚到哪、点哪）。
2. **定音色**：按下面的「音色选择」挑 2–3 个候选，用同一句开场白各生成一个试听，告诉用户试听文件的路径，让用户挑定。用户之前已经指定过音色的，直接用。
3. **生成配音**：每个镜头生成一个音频文件，放到临时目录，按顺序命名 `01.mp3`、`02.mp3`……，并记下每段时长。
4. **录制**：`record_start` 后逐个镜头执行：
   - 先 `record_mark`（label 写镜头名，note 写这句解说）；
   - 马上做这个镜头的画面动作（滚动或点击要在开头 1 秒内开始）；
   - 等到「这段配音时长 + 0.3 秒」再进入下一个镜头。等待用一次 `browser_evaluate` 里的 `setTimeout` 完成，不要多次空等。
5. `record_stop` 后，把音频复制到 `record_timeline` 返回的 `audio_dir`，再用 `record_edit` 写入 `narration`。每段的 `at` 用对应标记的时间，`audio` 填 `audio/01.mp3` 这样的相对路径，`text` 保留（用作字幕）。
6. 选背景音乐（见下文），`record_edit` 的 `music` 设置好后，用 `preview: true` 出预览。

用户自己操作的录制：`record_start` 后告诉用户可以开始了，用户说好了再 `record_stop`，然后按「解说词」一节补解说。

网页录制只录当前标签页。录制中不要切换标签，否则画面会停住。

## 桌面软件录制

录桌面软件（微信、Word、VS Code、拾光自己……）用 `record_start` 的 `source`：

| 场景 | 用法 |
|---|---|
| 录某个软件 | `source: "window"`，`window` 写标题或进程名的一部分（不确定先 `list_windows`）。会把它切到前台；录的是它在屏幕上的位置，所以别让别的窗口挡住它 |
| 录整个屏幕 | `source: "screen"`（鼠标所在的屏幕；多屏用 `monitor`） |
| 让用户自己选 | `source: "select"`，用户框选区域或单击窗口后开始 |

- 用户说「录一下我的操作」：用 `select` 或 `screen` 开始，告诉用户可以操作了，并说明按 **Ctrl+Alt+R**（录屏快捷键）或说「好了」就停止。
- 默认**不录拾光自己的窗口**（画面里它是透明的，光标移到上面也不会画出来），所以用户可以把拾光放在旁边。录拾光自己的宣传视频时传 `include_self: true`。
- 拾光代为操作桌面软件时同样遵守上面的节奏规则和「先配音再录」流程：每个镜头先 `record_mark`，再做操作。
- 桌面录制里点击的是什么控件（按钮名、输入框）会自动识别，`record_timeline` 的 steps 里能看到「点击 保存（按钮）」「切换到窗口 xxx」，写解说词时用它。
- **桌面软件没有源头打码**。录完先 `record_timeline` 看录了哪些窗口，涉及聊天记录、账号、文件名等隐私时，问用户哪里需要打码，用 `record_edit` 的 `masks` 补马赛克，或让用户在「录屏截图 → 编辑」里框选。

## 音色选择

按视频类型选，不要只看「表现力」：

| 视频类型 | 选什么样的声音 | 语速 |
|---|---|---|
| 产品介绍、功能演示、科技类 | 明亮、清晰、偏年轻的声音，像发布会或科技博主 | 稍快（+10 到 +20） |
| 教程、操作步骤 | 平和、清楚、亲切 | 正常到稍快（0 到 +10） |
| 广告口播、促销 | 有活力、带笑意 | 快（+15 到 +25） |
| 故事、悬疑、纪录片 | 才用低沉、悬疑、讲故事类的声音 | 正常或稍慢 |

- **产品介绍和演示不要用悬疑解说、纪录片腔、低沉稳重的声音**，也不要把语速调慢。这类声音会让视频显得沉闷、节奏拖。
- 音色名称和 ID 以配音工具（例如用户的 `doubao-tts-voiceover` Skill）给出的音色表为准，按名称和描述挑符合上表的音色。
- 定下来后整条视频用同一个音色和语速。

## 背景音乐

只有解说会很单调，演示和宣传视频默认都要加背景音乐。

- 配乐从 `record_timeline` 返回的 `music_library` 里挑（来自配乐目录，默认「音乐/拾光配乐」）。子文件夹名就是风格：
  - 「科技产品」：产品介绍、功能演示；
  - 「轻快日常」：Vlog、生活类；
  - 「舒缓教程」：教程、操作讲解；
  - 「活力动感」：开场、快剪、宣传。

  同一风格下按曲名挑，同一个用户的连续几条视频尽量不要重复用同一首。不要用带人声的歌曲。
- 配乐目录里的 `来源与授权.txt` 记录了每首音乐的来源和授权；用户问版权时据此回答。
- `music_library` 为空时，告诉用户把配乐放进 `music_dir` 指向的目录；用户有能生成音乐的工具时，也可以生成后放进去。不要随便从网上下载来路不明、可能有版权问题的音乐。
- 设置：`record_edit` 的 `music: {"path": "...", "volume": 0.25}`。有解说的地方音乐会自动压低（`duck` 默认 0.35），开头淡入、结尾淡出，音乐不够长会自动循环。
- 解说听不清时调低 `volume`（0.15–0.2）；没有解说的纯演示可以调到 0.4–0.5。

## 解说词（补写或改写时）

1. `record_timeline` 读出步骤标记、点击和页面切换（带时间和按钮文字）。
2. 按节奏规则写：口语、短句，说「做什么、能得到什么」，不念按钮全名；不要出现被打码的内容；开头一句介绍，结尾一句总结。
3. 先把解说词列给用户确认，再用 `record_edit` 的 `narration` 写入。没有配音时导出只出字幕。

## 配音工具

录制器不内置任何配音服务。音频由用户的配音工具生成：优先用用户已有的配音 Skill（例如 `doubao-tts-voiceover`），没有时问用户用哪个 CLI，并以它的 `--help` 为准。凭据由工具自己管理，不要让用户把密钥贴进对话，也不要写进命令行参数。

## 打码

- 网页录制：密码框、手机号、身份证、邮箱、银行卡、密钥默认在页面上就被模糊，录到的画面里没有明文。
- 桌面录制：没有自动打码，只能录完补（见上）。
- 页面打码要在**开始录制之前**配置：让用户在「插件 → 录屏与截图」设置里加 CSS 选择器或正则。
- 录完才发现漏了：用 `record_edit` 的 `masks` 补马赛克，也可以让用户在「录屏截图 → 编辑」里框选。
- 导出后**一定提醒用户看一遍成片**，确认没有漏掉的敏感信息，再对外发。

## 剪辑与放大

- 等待加载、操作失误的片段用 `cuts` 剪掉。
- 自动放大不理想时，用 `zooms` 指定放大段；`focus` 为固定焦点，不写则跟随光标。传 `"auto"` 恢复自动。
- 这些也都可以让用户在「录屏截图 → 编辑」里调。

## 字幕样式

- `record_edit` 的 `subtitle_style`：直接给预设名，或在预设上覆盖个别参数。
  - `classic`：白字 + 半透明黑底（默认，适合教程）
  - `variety`：综艺花字——站酷快乐体、黄橙渐变、白色 + 深棕双层粗描边、投影、弹出动画（适合宣传、轻松风格）
  - `minimal`：白字黑描边，无底框
  - `karaoke`：随朗读进度逐字变黄
- 想更花：`{"preset": "variety", "fill": ["#7CF7FF", "#2E8BFF"], "strokes": [{"width": 16, "color": "#0B1E4A"}, {"width": 7, "color": "#FFFFFF"}], "highlight": ["#FFE45C", "#FF9F1C"]}`。动画可选 pop / fade / slide / typewriter / karaoke / none。
- 解说词里用【】括出重点词（如「这个功能【超好用】」），字幕里会换成 highlight 颜色；`.srt` 里自动去掉括号。每条解说 1–2 个重点词就够，别满屏都是。
- 字体：`font` 可填 kuaile（站酷快乐体）、huangyou（站酷庆科黄油体）、xiaowei（站酷小薇）、mashan（马善政毛笔），首次导出时自动下载（免费可商用）；也可以填用户放进字体目录的文件名或系统字体文件名。

## 代码片段（片头、章节卡、贴纸）

成片不一定全是录制画面。用 `record_edit` 的 `scenes` 加网页做的片段，导出时逐帧渲染进视频：

- **insert**：插在源时间 `at` 处、独占画面，原画面在那里暂停（片头 `at: 0`，片尾 `at` = 录制时长，章节卡放在新步骤开始的时间）。
- **overlay**：从 `at` 开始叠在录制画面上，背景透明（名牌条、标注圆圈、综艺贴纸）。
- 先用内置模板：`{"id": "intro", "template": "title", "at": 0, "duration": 4, "vars": {"title": "…", "subtitle": "…"}}`。模板清单和可填参数在 `record_timeline` 的 `scene_templates`。
- 模板不够就自己写 `html`（完整网页）：画布宽 1920 CSS px、高按画面比例（通常 1080）；用 CSS 动画（`animation` + `animation-delay`，`forwards` 停在最后一帧）或定义 `window.renderFrame = (t) => {...}` 按秒画；`window.SG_DURATION` 是片段时长，做退场动画用；overlay 的页面背景必须透明。时间由导出接管，`setTimeout`、`requestAnimationFrame`、`Date.now()` 都按视频时间走，不要用随机数（每帧会不一样），要随机就用固定种子。字体可以直接用 `"ZCOOL KuaiLe"`、`"ZCOOL QingKe HuangYou"`。
- **每次加或改片段后，先 `record_scene_preview` 再 `read_image` 看效果**，文字溢出、颜色难看就改，确认后再导出。
- 解说想盖在插入片段上，把那条解说的 `at` 设得比片段的 `at` 早 0.05 秒；同一时刻的解说会排在片段之后。
- `scenes` 是整体替换：改一个片段时，其它片段也要原样带上（`record_timeline` 里有现有列表，不带 html 和 template 的项沿用原来的文件）。
- 节制使用：一条 1–2 分钟的视频，片头 + 片尾 + 2–3 个章节卡或贴纸就够了。

## 导出

- `record_export`。宣传视频用 `style: "padded"`，字幕用 `variety`，配上片头片尾。有代码片段时首次导出要启动后台浏览器逐帧渲染，片段越长越慢（5 秒片头约 10–20 秒），渲染结果会缓存。字幕默认画进画面，同时生成同名 `.srt`。
- 导出结果里的 `tightened_s` 是紧凑节奏剪掉的秒数，`duration_s` 是成片时长。成片超过 90 秒时，告诉用户可以删减哪几段。
- 首次导出会准备 ffmpeg，可能需要下载几十 MB，提前告诉用户。
