# 桌面软件操控

## 基本流程

1. `desktop_window`（action=list）确认窗口；软件没开就 `action=open`（target 写程序名或路径），返回新窗口。
2. `desktop_snapshot` 看控件结构。大窗口用 `query` 只看相关部分，例如 `query: "保存"`。
3. `desktop_action` 操作。target 优先用 `ref`，或直接写 `name` + `role`（不必先快照）。多步操作用 `steps` 一次提交。
4. 看返回的 `effect`：`opened_windows` 表示弹出了对话框或新窗口，`target_closed` 表示窗口关了，`title_changed` 表示比如文件名变了。出现对话框时对它 `desktop_snapshot`（window 写对话框标题）后再继续。
5. 收尾时用 `read`、快照或截图核对结果，不要把"已点击"说成"已完成"。

## 定位优先级

1. **ref / name+role**：靠控件接口，最稳、最快，窗口在后台也能操作。
2. **target.text**：控件树稀疏（快照返回 `sparse: true`）时，截图加本地 OCR，按画面上的文字点击。适合自绘界面、部分 Electron 应用和游戏启动器。同一段文字出现多处时用 `index`。
3. **target.visual**：没有文字的图标按钮。需要用户已配置 Jev。
4. **target.point**：先 `desktop_screenshot` 看图（模型能看图时图片会直接附上；不能看图就加 `ocr=true`），再按截图像素坐标点击。

## 动作要点

- `click` 默认先走控件接口（Invoke/Select/Toggle/Expand），返回的 method 说明实际用了哪种方式。某些程序对接口调用没反应时，改用 `method: "mouse"` 重试。
- `type`：输入框默认先清空再整值写入（Value 接口）。文档、富文本编辑器默认在光标处键盘输入。有的程序只认键盘事件，此时用 `method: "keys"`。
- `select`：下拉框给 `option`，会自动展开、选择、收起。列表项、标签页直接 `click`。
- `set_checked`：复选框按目标状态切换，是幂等的。
- `press`：快捷键往往最高效，例如 Ctrl+S 保存、Ctrl+N 新建、Alt+F4 关闭、F2 重命名、`"Alt F"` 打开文件菜单。按键会发给前台窗口，所以会先把目标窗口切到前台。
- `read`：读控件文字。不给 target 时读整个窗口。文档和编辑器能读全文。
- `wait`：等某个控件出现或消失（`gone: true`），比如等"正在保存"消失、等对话框弹出。不要用固定休眠。

## 常见情况

- **菜单和弹出层**：菜单、下拉列表、右键菜单展开后，会作为单独区块出现在下一次快照里。编号要重新取。
- **Electron 应用**（VS Code、飞书、钉钉、Slack 等）：控件树常常很稀疏，直接用 `target.text`。
- **微信/QQ 等**：部分界面是自绘的，用 OCR 定位。给人发消息属于对第三方发送，必须先确认对象和内容。
- **管理员权限的软件**：系统不允许普通权限的拾光操作它，工具会直接报错，照实告诉用户即可。
- **黑名单**：密码管理器等默认不允许操作，用户可以在插件设置里调整。
- 文件对话框（打开/另存为）：最稳的做法是在"文件名"输入框里 `type` 完整路径，再 `press` Enter。

## 安全

- 发送消息、提交表单、删除、付款、修改系统设置，执行前要说明影响并得到用户同意。
- 不读取、不回显密码框内容（快照里显示为 `***`）。
- 只操作当前任务需要的窗口。用户正在用的窗口被切到前台可能打断他，必要时先告知。
